# 仕様書: Pico 2W マスターコントローラー ファームウェア

> 親仕様書: [`00-system-overview.md`](./00-system-overview.md) / 共通プロトコルは親仕様書 §4 を参照。

## 1. 背景・目的

- 自作スイッチャーの**マスターノード**。役割は**縮小**され、以下のみを担う（親仕様書 §2.1）:
  1. 全スイッチングモジュール（CH32V003）を **I2Cマスター**として集約。
  2. 集約した SW/VR 状態を **USB-HID** としてPCへ伝達。
  3. PCが算出したバックライト色を **HID出力レポート**で受領し、I2Cで各モジュールへ配布。
  4. 全体設定の保持（PC経由で保存/更新）。
  5. （任意）Wi-Fi/BT によるワイヤレス接続。
- **タリー抽出（HDMI DDCスニッフィング）機能は削除**（タリーは外部デバイスが担当、親仕様書 §7）。

## 2. 機能要件

### 2.1 モジュール集約（I2Cマスター）
- [ ] スロットごとに1本ずつ引き出されたI2Cバス（`MODULE_BUS_COUNT`=5本、いずれもアドレスは `0x30` 固定）を定期ポーリングし、各モジュールの `0x00 STATE`（SW状態/VR×2）を取得（親仕様書 §4.5）。**モジュール番号 = バス（スロット）番号**。
- [ ] I2Cコントローラは2基（i2c0/i2c1）しか無いため、同じコントローラを共有するバス（i2c0: バス1,3,5 / i2c1: バス2,4）はピン機能の付け替えで時分割する。非選択バスは内蔵プルアップでHigh（アイドル）に保つ。
- [ ] 接続中モジュールを検出（ACK有無）して `module_present` ビットマップを構築。未接続/不通はタイムアウトしてスキップ（全体を止めない）。
- [ ] ポーリング集約周期は 1kHz 目安。VRは間引き/デッドバンドで無駄な更新を抑制。

### 2.2 USB-HID デバイス（PCへ集約状態を送信）
- [ ] ベンダー定義 HID デバイスとして列挙。**入力レポート `0x01`**（親仕様書 §4.1）で全モジュールのSW状態・VR値・`module_present`・`seq` を送出（状態通知型。押下エッジ検出はPC側）。
- [ ] 状態変化時に即時送出＋一定レートでの定期送出（取りこぼし対策）。
- [ ] `controller_id`（main/sub）は HID シリアル文字列または保存設定で提示。

### 2.3 バックライト配布（HID出力→I2C）
- [ ] **HID出力レポート `0x02`**（`module_index` + 4灯RGB, 親仕様書 §4.1）を受領し、対応モジュールの I2C `0x10 BACKLIGHT` へ書き込む。
- [ ] 受領キューを設け、I2C書き込みでメインループ/HID受信をブロックしない。

### 2.4 設定保持（PC経由）
- [ ] `controller_id`・モジュール割付ヒント・ネットワーク資格情報等を不揮発（フラッシュ）に保存。
- [ ] 設定の投入はPC経由（HIDフィーチャーレポート、または §2.5 のワイヤレス制御チャネル）。設定の正はPC（親仕様書 §4.6）。

### 2.5 ワイヤレス接続（任意）
- [ ] Pico 2W の CYW43 を用い、PCから投入した資格情報で **Wi-Fi**（または **BT**）接続を確立できる。
- [ ] HIDが使えない/無線運用時の代替経路として、SW/VR状態の送信・バックライト受領を同等に行う制御チャネルを提供（例: WebSocket/UDP over Wi-Fi）。
- [ ] 未設定時は無効（USB-HIDのみで動作）。

## 3. 技術スタック

- **MCU**: Raspberry Pi Pico 2W（RP2350 + CYW43 Wi-Fi/BT）。
- **開発環境**: Pico SDK（C/C++）。
- **USBスタック**: TinyUSB（ベンダーHID: 入力＋出力レポート）。
- **I2C**: ハードウェアI2C（マスター、i2c0/i2c1の2基を5バスで時分割）。基板に外付けプルアップが無いため内蔵プルアップを使い、バスクロックは100kHzを既定とする。
- **Wi-Fi/BT**: CYW43 + lwIP（Pico SDK同梱）。

## 4. 非機能要件

- SW状態→HID送出のレイテンシは数ms以内。
- 1モジュールのI2C不通が集約全体を止めない（タイムアウト・スキップ）。
- USB直結を主経路とし、無線は任意の代替経路。

## 5. ハードウェア接続

```text
[ モジュール0 CH32V003 ]─ バス1 (GPIO20/21) ─┐   全モジュール addr 0x30 固定
[ モジュール1 CH32V003 ]─ バス2 (GPIO26/27) ─┤   (モジュール番号 = バス番号)
[ モジュール2 CH32V003 ]─ バス3 (GPIO4/5)   ─┼──→ [ Pico 2W (I2C master) ] ──(USB-HID)──→ メインPC
[ モジュール3 CH32V003 ]─ バス4 (GPIO2/3)   ─┤                          └──(任意) Wi-Fi/BT ──→ メインPC
[ モジュール4 CH32V003 ]─ バス5 (GPIO0/1)   ─┘
```

- 物理的にはモジュール同士が数珠つなぎで、先頭がバス1を消費し残りを次段へ渡す（親仕様書 §4.5）。

- 旧「HDMI DDCタリー抽出ドングル」結線は本改訂で**廃止**。
