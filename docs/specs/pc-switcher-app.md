# 仕様書: PC常駐アプリ（映像エンジン & 制御ハブ）

> 親仕様書: [`00-system-overview.md`](./00-system-overview.md) / 共通プロトコルは親仕様書 §4 を参照。

## 1. 背景・目的

- 本システムの「脳」となるPC常駐アプリケーション。異種プロトコル映像入力（NDI / WebCam(UVC) / SRT）を**OBSのように自由に追加**して低遅延デコードし、GPU上で**2系統ME（PGM1/PGM2）**として PiP合成、仮想カメラ×2／HDMIへ出力する。
- コントローラー入力（USB-HID の集約状態）を受け付け、バックライト色を算出してPicoへ返し、タリー状態をUDP配信し、設定WebUI/APIをホストする統合制御ハブとして機能する。

## 2. 機能要件

### 2.1 ソース管理（OBS的な自由追加）
- [ ] ソースを**自由に追加・削除・並べ替え・複製**できる（OBSのソース概念に相当）。設定は永続化。
- [ ] ソース種別:
  - **NDI**: NDI SDK（導入済み前提）で検出・受信。SDK未検出時は**ダウンロード導線（案内リンク/手順）**をUIに表示。ソースはNDI名で選択。
  - **WebCam (UVC)**: OSのキャプチャデバイスから選択（デバイス/解像度/FPS）。
  - **SRT（ATEM入力等）**: Listener（Port 9000）/Caller を選択可能。URL・`latency` を指定。ATEM MiniのPGMはSRT入力ソースとして扱う。
- [ ] 各ソースは名前・種別・種別別設定・解像度・現在ステータス（接続中/切断/エラー）を保持し、`GET /api/v1/sources` で一覧取得可能（親仕様書 §4.2）。
- [ ] 各入力はスレッド分離してノンブロッキングでデコード（1系統の切断が他系統に波及しない）。動的追加/削除/再接続に対応。

### 2.2 GPUレンダリング・2系統ME PiP合成エンジン
- [ ] **PGM1 / PGM2 の2系統独立ME**を保持し、各系統が独立した合成出力を持つ。各系統に **PVW（PVW1 / PVW2）** を備え、`TAKE` で PVW→PGM 切替。
- [ ] 各系統ごとに、任意ソースをレイヤとして **PiP合成**（座標・サイズ・Zオーダー・不透明度・クロップ）。同一ソースを両系統に載せられる。
- [ ] デコードフレームをGPUテクスチャとして直接合成（CPU負荷最小化）。レイアウト変更はミリ秒単位でリアルタイム反映。
- [ ] 物理モジュールのSWマトリクス（`pgm{1,2}×src{1,2}`）入力で、対象ソースの各PGMバスへの載せ降ろしをホット操作。VR（トランジション/汎用パラメータ）を反映（親仕様書 §4.2 `vr_target`）。
- [ ] シーンプリセットの保存・読み込み。

### 2.3 マルチビュー（4x4 コンフィギュラブル）
- [ ] **4x4（16セル）のマトリクス・マルチビュー**を提供。各セルに `PGM1` / `PGM2` / `PVW1` / `PVW2` / 任意 `SRCn` / 空 を**自由配置**（ATEMマルチビューを意識）。
- [ ] レイアウトは保存可能（`PUT /api/v1/multiview`）。ラベル・トリム表示・PGM/PVWの枠色（赤/緑）を表示。
- [ ] メインウィンドウ表示に加え、サブオペレーター用に全画面プロジェクター出力も可能。

### 2.4 出力
- [ ] **仮想カメラ×2**（DirectShow/Media Foundation 仮想デバイス）を提供し、既定で PGM1→VCAM1 / PGM2→VCAM2。割当は変更可能。
- [ ] **HDMI／物理ディスプレイへの全画面出力**。指定ディスプレイに PGM1/PGM2 等を割当。**マウスカーソル非表示**・全画面。
- [ ] 出力割当は `PUT /api/v1/outputs`（親仕様書 §4.2）で動的変更。
- [ ] （任意）録画・配信出力は将来拡張の枠を用意。

### 2.5 Webサーバー・API・設定ホスト
- [ ] ポート **8080** で HTTP/WebSocket サーバを内蔵起動し、**設定WebUIをホスト**（PCが設定の正）。
- [ ] 親仕様書 §4.2 の各エンドポイント（sources / program / multiview / outputs / modules / pico/network）を提供。
- [ ] スマホ等のリモートUI（`phone-web-bridge`）から**ネットワーク経由**で接続可能（同一LAN/Wi-Fi、必要に応じ認証）。
- [ ] Pico の設定（`controller_id`・モジュール割付・Wi-Fi/BT資格情報）を**PC経由でPicoへ投入・保存**（親仕様書 §4.6）。

### 2.6 コントローラー入力（USB-HID）とバックライト算出
- [ ] Pico 2W の **USB-HID 入力レポート**（親仕様書 §4.1）を購読し、集約されたSW状態・VR値を取得。押下エッジは状態差分で検出し、入力を直列化。
- [ ] 現在のPGM1/PGM2・PVW・選択状態から**各スイッチのバックライト色を算出**し、**HID出力レポート**でPicoへ返す（例: PGMオン=赤/PVW=緑/選択可=淡色/消灯）。
- [ ] （任意/無線運用）HIDが使えない場合、Wi-Fi/BT 経由の制御チャネルで同等のやり取りを行う。

### 2.7 タリー配信（外部デバイス向け・維持）
- [ ] 現在の PGM1/PGM2/PVW1/PVW2 のソースIDを `255.255.255.255:9999` にUDPブロードキャスト（親仕様書 §4.3, 2系統対応ペイロード）。
- [ ] 状態変化時に即時送出＋定期冗長送出。受信は外部ワイヤレスタリー子機（`wireless-tally.md`）。

> **注**: 本アプリ自身はタリーを算出・配信するのみ。HDMI DDC等からのタリー「抽出」機能は本システムから削除（親仕様書 §7）。

### 2.8 ATEM遠隔制御クライアント（維持）
- [ ] ATEMプロトコル（UDP 9910）のクライアントとして振る舞い、指定IPの ATEM Mini を遠隔制御する。
- [ ] **ATEMは二役**: ①その PGM を SRT/NDI 等の**入力ソース**として受ける（§2.1）と同時に、②本クライアントで**遠隔制御**する。
- [ ] **src1〜4 のATEM一括管理**運用に対応: モジュールSW/VRの割当（親仕様書 §4.2 `PUT /api/v1/atem`）に従い、コントローラー入力を ATEM コマンド（Program/Preview入力切替・Cut/Auto）へ変換して中継する。
- [ ] 接続・ハンドシェイク・再接続（バックオフ）・接続状態通知。未接続時のコマンドはドロップ方針を明示。
- [ ] 既存実装資産 `Switcher.Atem`（`IAtemController`）を継続利用する。

## 3. 技術スタック（確定）

- **言語/FW**: C# / .NET 9（WPF）※Windows 10/11 前提。
- **映像デコード・ストリーミング**: GStreamer（GstSharp）。SRT/NDI/UVC をスレッド分離でデコード。NDIは NDI SDK 前提（未導入時は導線表示）。
- **GPU合成**: DirectX 11（Vortice）。フレームをGPUテクスチャへ直接転送しシェーダで合成。2系統MEを個別レンダーターゲットで保持。
- **仮想カメラ出力**: 仮想カメラデバイス（DirectShow/MFフィルタ）×2。
- **Webサーバー**: ASP.NET Core Kestrel（アプリ内蔵）。
- **ATEM遠隔制御**: 既存 `Switcher.Atem`（UDP 9910, ATEM純正プロトコル）を継続利用。

## 4. 非機能要件

- 低遅延: 映像パスはゼロ〜低バッファ。SRTは `latency` 20〜50ms目安。
- 多ソース同時デコード時もGPUオフロードでCPU使用率を抑制。
- 1系統の障害（切断・デコードエラー）が全体を巻き込まない耐障害設計。
- SW状態→PGM反映は数ms〜十数ms（HID経路）。

## 5. UI/UX 設計方針

- メインウィンドウに 4x4 コンフィギュラブル・マルチビュー（PGM1/PGM2/PVW1/PVW2/SRCn）を表示。
- ソースドック（追加/削除/並べ替え）・プロパティ（種別別設定）・出力割当・モジュール割付の各パネル。
- サブオペレーター用に全画面プロジェクター出力（カーソル非表示）。
- ダーク基調（配信現場の眩しさ抑制）。詳細設定はWebUIからも操作可（同一API）。
