# 仕様書: PC常駐アプリ（映像エンジン & 制御ハブ）

> 親仕様書: [`00-system-overview.md`](./00-system-overview.md) / 共通プロトコルは親仕様書 §4 を参照。

## 1. 背景・目的

- 本システムの「脳」となるPC常駐アプリケーション。10ch以上の異種プロトコル映像入力（UVC / NDI / SRT）を低遅延でデコードし、GPU上でPiP合成して仮想カメラ／HDMIに出力する。
- 同時に、コントローラー入力の受付（WebAPI/WebSocket）、独自タリーのUDP送出、ATEMの遠隔制御クライアントを内包する統合制御ハブとして機能する。

## 2. 機能要件

### 2.1 マルチソース入力マネージャー
- [ ] UVC（USBキャプチャ）、NDI、SRT（Listenerモード, Port 9000）を**最大10系統以上**同時に待ち受け・デコードする。
- [ ] 各入力はスレッド分離してノンブロッキングでデコードする（1系統の切断が他系統に影響しない）。
- [ ] 入力ソースの動的な追加・削除・再接続に対応する。
- [ ] 各ソースの名前・プロトコル・解像度・現在ステータス（接続中/切断/エラー）を保持し、WebAPIで一覧取得可能にする。

### 2.2 GPUレンダリング・PiP合成エンジン
- [ ] デコードした各フレームをGPUテクスチャとして直接合成（CPU負荷を最小化）。
- [ ] 指定した座標・サイズ・Zオーダー・不透明度・クロップに従いソースを合成。
- [ ] コントローラー／WebUIからのコマンドでPiPレイアウトをミリ秒単位でリアルタイム変更可能。
- [ ] PGM（本番）／PVW（プレビュー）の2系統の合成結果を管理し、TAKE（切替）操作に対応。
- [ ] シーンプリセットの保存・読み込み。

### 2.3 出力
- [ ] 合成結果を**仮想カメラ**（DirectShowフィルタ、OBS Virtual Camera相当）としてOSに認識させる。
- [ ] HDMI／Type-C等の物理ディスプレイへのフルスクリーン出力（PGM出力）。
- [ ] （任意）録画・配信出力は将来拡張として枠を用意。

### 2.4 Webサーバー・API
- [ ] ポート **8080** で HTTP/WebSocket サーバを内蔵起動。
- [ ] `POST /api/v1/config`（親仕様書 §4.2）で入力ソース設定・PiPレイアウトを変更。
- [ ] `GET /api/v1/sources` で全入力ソースの一覧・ステータスを返す。
- [ ] WebSocket でコントローラー入力イベント（親仕様書 §4.1）をリアルタイム受信（遅延5ms以下目標）。
- [ ] 入力イベントはキューで直列化し、メイン/サブ同時操作時も競合・取りこぼしを防ぐ。

### 2.5 独自タリー配信サーバー
- [ ] 現在の PGM/PVW ソースIDを `255.255.255.255:9999` にUDPブロードキャスト（親仕様書 §4.3）。
- [ ] 状態変化時に即時送出＋定期冗長送出。

### 2.6 ATEM遠隔制御クライアント
- [ ] ATEMプロトコル（UDP 9910）のクライアントとして振る舞う。
- [ ] メイン側コントローラーの特定ボタン入力を ATEM コマンド（シーン/入力切替 等）に変換し、指定IPのATEM Miniへ送信（コントローラーの中継）。
- [ ] ライブラリは既存資産（例: C#向け AtemSharp 系）の利用を検討。

## 3. 技術スタック（確定）

- **言語/FW**: C# / .NET 9（WPF または WinForms）※Windows 10/11 前提
- **映像デコード・ストリーミング**: GStreamer（GstSharp）。SRT/NDI/UVC/RTMPをスレッド分離でデコード。
- **GPU合成**: DirectX 11/12（または OpenGL / WPF-D3DImage）。フレームをGPUテクスチャに直接転送しシェーダで合成。
- **仮想カメラ出力**: DirectShow Filter（レジストリ登録型DLL）。
- **Webサーバー**: ASP.NET Core Kestrel（アプリ内蔵）。

## 4. 非機能要件

- 低遅延: 映像パスはゼロ〜低バッファ。SRTは `latency` 20〜50ms目安。
- 10ch同時デコード時もGPUオフロードによりCPU使用率を抑制。
- 1系統の障害（切断・デコードエラー）が全体を巻き込まない耐障害設計。
- コントローラー→切替反映 5ms以下（WebSocket経路）。

## 5. UI/UX 設計方針

- 常駐アプリのメインウィンドウにマルチビュー（全入力＋PGM/PVW）を表示。
- サブオペレーター用にソースプロジェクター（全画面）出力を提供（ATEMマルチビュー確認等）。
- ダーク基調（配信現場の眩しさ抑制）。詳細な設定操作はWebUI（別仕様書）側に委譲可。
