# 仕様書: スマホ経由Web設定UI（ネットワーク中継）

> 親仕様書: [`00-system-overview.md`](./00-system-overview.md) / 共通プロトコルは親仕様書 §4 を参照。

## 1. 背景・目的

- スマホのブラウザ（またはPWA）からアクセスする**リモート設定/操作UI**。従来のUSB-OTG＋Web Serial 中継を廃し、**スマホのネットワーク回線（Wi-Fi）経由でホストPCへ接続**する構成に改める（USB-HIDの代替＝ワイヤレス化の意図）。
- 物理ケーブルの引き回し制約を、スマホ＋ネットワークで解消する。設定の正はPC常駐アプリが保持し、本UIはそのクライアント。

## 2. 機能要件

### 2.1 ネットワーク接続（USB Web Serial からの置換）
- [ ] メインPC常駐アプリ（`:8080` の HTTP/WebSocket）へ**同一LAN/Wi-Fiのネットワーク経由**で接続する。接続先ホスト/ポートは設定可能（mDNS/手動IP）。
- [ ] Pico 2W の入力は**PC側でUSB-HIDとして集約**されるため（親仕様書 §4.1）、本UIは原則としてPC経由の状態を購読・操作する（スマホ↔Pico の直接USB中継は行わない）。
- [ ] （任意）Pico が Wi-Fi/BT でワイヤレス接続する構成では、PCがそれをブリッジし、本UIからは常にPC経由で扱う。
- [ ] 接続状態（ネットワーク/WebSocket）の可視化と自動再接続（指数バックオフ）。

### 2.2 スイッチャー設定UI（GUI）

本UIは**設定専用**。本番操作（TAKE）とタリー監視はPCコンソール／モジュールパネルの担当とする。

- [ ] ソース管理: 一覧（`GET /api/v1/sources`）＋設定内容（`GET /api/v1/sources/definitions`）を取得し、
      **NDI / WEBCAM / SRT / IMAGE / HTML / MIX** の追加・更新・削除・並べ替えを行う。音声モード
      （`audio_mode`: OFF/ON/AFV）も設定する。
- [ ] 入力デバイス選択: `GET /api/v1/devices/{webcam|ndi}` から選択させる（手入力に頼らない）。SRTは
      `GET /api/v1/srt/setup` の受信ガイダンスを表示し、Listener/Caller を選ばせる（モードはURLの
      `mode=` クエリに載せる。親仕様書 §4.3）。
- [ ] **2系統ME（PGM1/PGM2）**のプログラム構成・PiPレイアウト（サイズ/位置/クロップ/不透明度/Zオーダー）を
      スライダー/ドラッグで視覚的に編集（`POST /api/v1/program`、`take` は常に false）。過剰送信はデバウンス。
- [ ] **マルチビュー**の割当編集（`GET/PUT /api/v1/multiview`）。任意の行×列（4〜6）と**セル結合**に対応し、
      `grid`＋`regions` 形式で送出する（旧 `cells` 16セル形式は読み込み時に変換）。
- [ ] **出力割当**（PGM1/PGM2 → `VCAM1` / `HDMI1`〜`HDMI3` / `NDI1`〜`NDI3` の可変テーブル。sink の追加・削除、
      NDI送信名も含む。上限は Webcam 1・HDMI 3・NDI 3・合計6。親仕様書 §4.2）の編集（`GET/PUT /api/v1/outputs`）。
- [ ] **音声出力**: プログラムバス→再生デバイスのルーティング編集（`GET /api/v1/audio/devices`,
      `GET/PUT /api/v1/audio/outputs`）。1バスを複数デバイスへ出せる。
- [ ] **モジュール割付・VR割当**（`GET/PUT /api/v1/modules`）と **Picoネットワーク設定**
      （`PUT /api/v1/pico/network`、資格情報のため書き込み専用）の編集。
- [ ] **ATEM 遠隔制御**: 接続設定・ネットワーク検索・モジュールSW→ATEMコマンド割付・ATEMのストリーミング出力
      設定（`GET/PUT /api/v1/atem`, `GET /api/v1/atem/discover`, `POST /api/v1/atem/streaming`）。
- [ ] シーンプリセットの保存・読み込み。
- [ ] 各パネルは適用前に必ず現在値を読み出す（各 `PUT` はテーブル全体を置換するため、読まずに適用すると
      既存設定を潰す）。

## 3. 技術スタック

- **フロントエンド**: React / TypeScript（Vite）。
- **UI**: Tailwind CSS（ダークモード標準）。
- **通信**: WebSocket / REST（PC常駐アプリ `:8080`, `/api/v1/*`）。ネットワーク経由（Wi-Fi）。
- **配信**: ビルド成果物（`dist`）をPC常駐アプリの Kestrel が `wwwroot` として**APIと同一オリジンで**配信する
  （`http://<PC>:8080/`）。別オリジンから開くとブラウザがAPI呼び出しをブロックするため、`:8080`（0.0.0.0待受）
  に CORS を開けるのではなくページ側を同一オリジンへ寄せる。クライアントの既定接続先はページ自身のオリジン。
- **接続補助**: mDNS/手動IP でホスト発見（同一オリジンで開けない場合の上書き）。必要に応じて簡易認証（トークン等）。

## 4. 非機能要件

- リモート操作の遅延を最小化（ネットワーク経由の設定反映は実用上問題ない範囲）。
- ネットワーク断時の再接続・エラー表示。同一LAN前提（HTTPS/認証は運用に応じ）。
- スキーマは PC側（親仕様書 §4.2/§4.3）と型・JSONフィールド名を一致させる（IF互換）。

## 5. UI/UX 設計方針

- ダーク基調・大きめのタップターゲット（現場でのスマホ片手操作を想定）。
- 「接続先」と「設定」をタブ等で切替。眩しさを抑えた低輝度配色、状態はアイコン＋色で即判別。
- タリーは表示しない: PCのタリーは UDP ブロードキャスト（親仕様書 §4.3）のみで、ブラウザは受信できない。
  REST のミラーも無いため、本UIは設定専用としてタリー表示を持たない。
