Live video switcher · Windows

カメラも、スライドも、NDI も。PC 1台で切り替える。

Switcher は 2系統の M/E を持つライブ映像スイッチャーです。映像処理は OBS の コアである libobs に任せ、その上に本番で使えるスイッチャーの操作系を載せました。 物理コントローラー・Web・キーボードのどれからでも同じ1つの状態を動かします。

Signal path

映像がどこを通るかが、そのまま画面になっている

入力を選び、プレビューに載せ、CUT で本線に出す。それだけです。

入力カメラ · NDI · SRT · 画像 · Web ページ · MIX
→
PGM1 / PVW1M/E 1 — CUT・AUTO
PGM2 / PVW2M/E 2 — 独立して動く
→
出力仮想カメラ · NDI ×2 · HDMI 全画面 · 音声デバイス

Why

この構成でしかできないこと

Shared input pool

同じカメラを同時に何度でも

入力は 1 回だけ開き、全系統がそのインスタンスを共有します。1台のカメラを PGM1 と PGM2 と MIX に同時に出せるのは、この単一プロセス構成だからです。

Dual M/E

2系統がぶつからない

PGM1/PVW1 と PGM2/PVW2 は完全に独立。片方の CUT がもう片方に波及しません。配信用と 会場スクリーン用で別の絵を同時に作れます。

MIX source

合成した絵も「1つのソース」

複数のソースを自由配置した MIX は、カメラとまったく同じ扱いになります。バスにも、 マルチビューにも、物理スイッチにも割り当てられます。

NDI

プラグイン不要の NDI

NDI SDK を直接使って入出力を実装しています。OBS 用の NDI プラグインは要りません。 NDI ランタイムが無い PC でも同じバイナリがそのまま動き、NDI 機能だけが無効になります。

One source of truth

操作経路が競合しない

物理コントローラー・Web・画面のどれから触っても、状態変更は同じ 1 か所を通ります。 同時に操作してもタリーやバックライトがずれません。

Audio follows video

音は映像についてくる

ソースを追加すればその音声も一緒に入ります。オンエア中だけ鳴らす AFV、常時鳴らす ON、 鳴らさない OFF をソースごとに選ぶだけ。PGM1 と PGM2 の音は別々の出力デバイスへ送れます。

Tally

オンエアが一目で分かる

マルチビューのセルは、内容がオンエアなら赤枠・ステージ中なら緑枠。カメラのセルも同じ ルールなので、バス表を追わなくても状態が読めます。
